# 经验｜以前好的现在坏了，中间改动多，就对半找

- 处境：升级依赖后一个测试挂了，上次通过到现在中间有 40 个提交
- 做法：用 git bisect 对半查找，6 次就定位到出问题的那个提交
- 结果：比一个个读提交快得多
- 通用说法：以前能用、现在不行、中间又改了很多时，不要逐个猜，把改动对半切开试，哪一半坏就再切那一半
- 适用于：以前是好的；之前还好好的；突然不行了；不知道哪一步弄坏的；中间改了很多
